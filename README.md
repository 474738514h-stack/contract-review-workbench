# 合同审查工作台

> 💡 **项目定位：** 面向企业法务与业务人员的企业级 Agent 落地应用。基于 LLM 与 Coze 工作流编排，实现非结构化合同文档的智能审查。通过结构化 Prompt 约束，完成合同类型识别、风险条款提取、法律引用核验及飞书报告生成，打造从“文档上传”到“合规审核”的完整闭环。

**核心技术栈/概念：** `LLM` `Agent` `RAG` `Function Calling` `Coze Workflow` `Prompt Engineering` `TypeScript` `Next.js`

---

给企业法务和业务负责人使用的合同审查页面。上传或粘贴合同后，服务端调用已配置的扣子工作流，并展示审查意见、法律引用核验、企业信息核验和飞书报告入口。

访问令牌只放在服务端环境变量中，不会出现在页面或浏览器代码里。

## 本地运行

```bash
npm install
cp .env.example .env.local
npm run dev
```

浏览器打开 `http://127.0.0.1:43123`。

不配置扣子时，页面使用演示数据，顶部显示「演示数据」，审查结果标注「当前为演示结果」，不会请求扣子，也不会消耗工作流额度。

在 `.env.local` 中配置后才会调用真实工作流：

- `COZE_PAT`：扣子个人访问令牌，只用于服务端。
- `COZE_WORKFLOW_ID`：已发布的扣子工作流 ID。
- `COZE_API_BASE`：可选，默认 `https://api.coze.cn`。
- `REVIEW_SOURCE`：设为 `mock` 时始终使用演示数据；设为 `live` 且令牌已填写时调用扣子。

工作流开始节点需要两个输入：`wenjian`（合同文件）和 `xuqiu`（审查要求）。页面会把合同类型、审查立场、重点审查内容和补充要求写入 `xuqiu`。

## 演示

1. 选择合同类型、审查立场和重点审查内容。
2. 上传 PDF、Word、TXT 或 MD 文件，或直接粘贴合同文本。
3. 点击“开始智能审查”。审查进行时按钮不可重复提交，四个步骤会依次变化。
4. 工作流返回后，可以按风险等级筛选、复制修改建议，并打开飞书报告。
5. 如果工作流在上传飞书报告前要求授权，按页面提示完成飞书授权后继续本次审查。
6. 如果扣子暂时无法调用，页面会提示错误，并展示标注为“当前为演示结果”的本地示例。最近几次审查会保存在本机浏览器中。
